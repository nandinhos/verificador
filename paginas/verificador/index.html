Fundação Teórica

O Padrão Epistêmico do Verificador

Definido no PROTOCOLO.md, este método formal estabelece as fronteiras do que é verdade verificada versus o que é mera suposição.

OBSERVED Comprovado

Fato atestado diretamente por arquivo lido, teste executado com saída bruta e exit code gravado, schema inspecionado ou comando físico rodado. A única base aceita como verdade factual.

INFERRED Deduzido

Conclusão lógica razoável derivada de dados previamente observados, mas ainda não comprovada em execução real. Deve ser explicitamente rotulada como hipótese em teste.

UNKNOWN Bloqueado

Informação ausente no contexto ou não verificável no repositório. Sob o protocolo, é proibido converter silenciosamente UNKNOWN em OBSERVED ou inventar fontes/dados ausentes.

Evolução do Produto

Do Terminal à Interface Gráfica

Hoje o Verificador opera como uma poderosa ferramenta de linha de comando no terminal. O roadmap projeta a evolução para um cockpit visual completo.

Fase 1 · Atual (MVP)

CLI & Terminal Harness

Operação direta no terminal e harnesses de engenharia (Antigravity, Claude, Kiro). Execução de scripts determinísticos, Language Server (LSP) em Node.js, IPC handlers e scaffolds de discussões investigativas.

Estado Atual: Em produção ativa no repositório nandinhos/verificador.
Fase 2 · Próxima Etapa

Barramento Integrado JARVIS

Conexão fluida entre JARVIS, Dev-Memory e Verificador Determinístico via protocolos MCP e APIs de eventos. O JARVIS consulta o Verificador para validar planos de código antes de aplicá-los.

Foco: Sincronização de memórias de trabalho e mediação de ações de alto risco.
Fase 3 · Futuro

Interface Gráfica Dedicada (GUI)

Dashboard visual completo para visualização gráfica de evidências em tempo real, grafos de dependência, matrizes de conciliação de dados, status de auditorias e cockpit interativo para o desenvolvedor.

Visão: Dashboard desktop & web com renderização visual de árvores de decisão e claims.
